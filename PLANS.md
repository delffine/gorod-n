# Планы дальнейшего развития проекта

Записано 2026-10-12. Тема: на чём держится связь с моделью ИИ и как перейти на другие модели (GPT, DeepSeek, Gemma).

## Где подключается модель

Подключение к Anthropic начинается в строке запуска `claude -p` в `auto/run.sh` (автопостинг) и в `auto/inbox.sh` (бот). Это Claude Code в неинтерактивном режиме. Ключ доступа он берёт из `~/.config/gorodn.env`: скрипт подгружает его через `set -a; . gorodn.env`.

Модель вызывается не один раз: каждый шаг агента — отдельный запрос к API Anthropic. Claude читает скилл, запускает `fetch_news.py`, решает, что дальше, вызывает Postmypost и так далее. Отсюда «turns 15, cost 0.55» в логе: 15 запросов за прогон. Фактчекер — отдельный субагент на Sonnet, тоже запросы к Anthropic.

Не через Anthropic идут картинки (Cloudflare FLUX), публикация (Postmypost) и сам бот (обычный Python, модель не нужна).

## Насколько сложно переключиться

Главное: от Claude мы зависим не через сам API, а через Claude Code как «оболочку агента». Логика проекта описана текстом в скилле: шаги, правила, субагент-фактчекер, MCP-подключения, права на файлы. Её выполняет Claude Code. Поэтому вариантов три.

### 1. Оставить Claude Code и подставить другую модель (легко, но рискованно)

Claude Code умеет ходить не напрямую в Anthropic, а через `ANTHROPIC_BASE_URL`. Туда можно поставить прокси-переводчик (LiteLLM, OpenRouter), который отправит запросы в GPT или Gemini. У DeepSeek, насколько известно, есть свой Anthropic-совместимый адрес. Работы на час.

Минус в качестве: Claude Code и наш скилл заточены под Claude. Другие модели хуже держат длинный многошаговый сценарий с инструментами, а ошибка здесь стоит дорого — дубль поста, пропуск фактчека, кривая запись в JSON. Это неподдерживаемый режим, сломаться может после любого обновления Claude Code.

### 2. Перейти на другую агентную оболочку (средне)

У OpenAI есть Codex CLI, у Google — Gemini CLI. Оба умеют MCP и инструкции из файлов проекта. Пришлось бы переносить скилл, субагента и настройки прав, а потом заново всё отлаживать. Несколько дней работы, и мы получаем ту же зависимость, только от другого вендора.

### 3. Переписать конвейер на Python, а модель звать только для текста (дольше всего, зато надёжнее всего)

Скачать новости, проверить дубли, сделать картинку, опубликовать через REST API Postmypost, записать JSON — всё это детерминированный код. Он у нас наполовину уже есть: `fetch_news.py`, `gen_image.py`, `post_json.py`, `inbox_bot.py`. Модель нужна только для четырёх задач:

- выбрать новость из списка;
- написать пост голосом Бендера;
- проверить факты;
- оценить картинку на брак (это нужно зрение).

Каждая задача — один запрос «промт → ответ», и такой запрос одинаково просто сделать к Claude, GPT, DeepSeek или Gemini. Модель меняется одной строкой в настройках, задачи можно даже раздать разным моделям.

Плюсом уйдут проблемы выходных 10–11.10: MCP-таймауты (REST вместо MCP), странные итоги в логе, «Claude решил не публиковать». Каждый прогон станет в разы дешевле. Работы примерно 2–4 дня с отладкой.

## Про Gemma

Это открытая модель, её запускают у себя. На нашем VPS с одним CPU и без видеокарты она не поедет, а через облачного провайдера смысла немного. Для задач агента (вариант 1 или 2) она слабовата, для одиночных задач из варианта 3 — вполне, если писать её текст и тут же проверять сильной моделью.

## Что бы я выбрал

Если цель — независимость от вендора и стабильность, то вариант 3. Если хочется просто попробовать другую модель «на посмотреть», то вариант 1, на отдельном ручном прогоне, не в cron.

Можно сделать гибрид: переписать на Python только публикацию и записи в JSON, где сбоило на выходных, а писательство пока оставить Claude.
